What it does

How it works

Your first-pass identifications define the search space: every peptide found becomes all of its allowed single-residue variants. Each variant must then pass three checks: validation, base-peptide rescoring and localization. Click a step for detail.

step where a substitution is created or tested selected
3bIn-silico mutagenesisSEARCH

Every peptide the first pass identified becomes all of its allowed single amino acid variants, and those variants become the second-pass search database. You don't supply a candidate list; it comes from what your first pass found.

Runs: TARSUS (Python), with a configurable substitution exclusion matrix

Scope

What it can and cannot do today

Can

  • Search any proteome you supply as FASTA. Validated on human and E. coli.
  • Check every variant against its unsubstituted (base) peptide before it is reported.
  • Localize each substitution to one residue with PyAscore.
  • Report abundance: variant over base peptide intensity (dpbp) for every call.
  • Map substitutions back to codons when you give a CDS FASTA (64 × 19 heatmap).
  • Resume a stopped run and record the exact code version that produced it.

Cannot, or needs from you

  • Needs an LSF cluster (bsub) on Linux x86_64 with a shared filesystem. There is no local mode for a full run. One master job sends thousands of PepQuery and FragPipe jobs to the cluster. Compute nodes must see the same paths as the login node. Only tarsus convert --local runs without LSF.
  • Reads Thermo .raw files only.
  • One substitution per peptide.
  • Cannot tell Ile from Leu at the destination: reported as I/L. Ile and Leu have the same mass (113.08406 Da). The origin residue is known from the genome; the destination is seen only by mass.
  • MSFragger and IonQuant are not included: each lab downloads them under their academic license.
  • The default MSBooster mode needs internet from compute nodes. Use --msbooster-models dia-nn when they are offline.
  • Some substitution classes are excluded by design (for example D→N and N→D), set in a configurable matrix.

Input

What you give it

uv run tarsus run --fasta proteome.fasta -i run1.raw -i run2.raw -o out/

Required

--fastarequired

Reference proteome FASTA (.fasta, .fa, .faa).

-i, --inputrepeatable

Thermo .raw files. Give one -i per file.

-o, --output-dirrequired

Run directory. Created and laid out step by step.

Optional

--queuegsla-cpu

LSF queue for every job. Set it to a queue on your cluster.

--cdsoff

CDS nucleotide FASTA. Turns on the 64 × 19 codon heatmap; without it that figure is skipped with a warning.

--msbooster-modelsbest

best picks online models (needs internet); dia-nn uses local models, offline.

--localize-tol0.01 Da

Step 11 fragment tolerance. 0.01 for Orbitrap MS2; 0.6 for ion-trap MS2.

--base-rescore-tol0.05 Da

Step 9 fragment tolerance for base-peptide rescoring.

--memory32000 MB

Memory for the master job.

When a run goes wrong

Run it again

Rerun the same command. Finished steps are skipped and the run picks up where it stopped.

Crashed jobs retry

A cluster job that dies at launch (exit 255) is resubmitted by LSF instead of failing the run, up to your cluster's requeue limit (5 on ours).

f13740f
Version on file

Each run saves the code version and the exact command in provenance.json, so any result can be traced back and rerun.

Get it running

Clone it, then let your coding agent set it up

The repository carries a setup guide written for coding agents such as Claude Code and Codex. It checks your cluster first and asks before every install.

Linux x86_64 LSF (bsub) shared filesystem uv + Python 3.11 MSFragger 4.4.1 + IonQuant 1.11.20: you download

With a coding agent

  1. Clone the repositorygit clone https://github.com/pilpelab/TARSUS.git
  2. Download the two licensed toolsAccept the academic license at msfragger.nesvilab.org, then put the files here:tools/_downloads/MSFragger-4.4.1.ziptools/_downloads/IonQuant-1.11.20.jar
  3. Open your agent in the repository and sayset up TARSUSIt follows the setup guide: preflight, install, tool check, first run.
By hand
git clone https://github.com/pilpelab/TARSUS.git
cd TARSUS
# put MSFragger-4.4.1.zip and IonQuant-1.11.20.jar in tools/_downloads/
uv venv --python 3.11
uv sync
make setup            # fetch and checksum the other tools
make test-tools       # every tool should print OK
make test-pdv-full

uv run tarsus run --fasta proteome.fasta \
  -i run1.raw -i run2.raw \
  -o out/ --queue <your-queue>

bjobs                 # master job status
tail -f out/master.log  # ends with: DONE: Pipeline complete.
